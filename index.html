Ch14：正規化與 Functional Dependency

Serializable

含圖解

並行執行的 schedule，如果最後結果等同於某一種「交易一個接一個連續執行」的結果，就稱為 Serializable。白話來說，雖然 transaction 看起來同時跑，但結果必須像排隊執行一樣正確。【建議畫圖：圖1 Serializable Schedule 比較圖，左邊畫 T1、T2 交錯執行，右邊畫 T1→T2 或 T2→T1 連續執行，標示兩邊結果相同】

Spurious tuple

含圖解

資料表分解後再 JOIN 回來時，產生原本不存在的多餘錯誤 tuple，稱為 Spurious tuple。白話來說，就是表拆壞了，JOIN 回來多出假資料。【建議畫圖：圖2 Spurious Tuple 圖，畫出兩張分解表 JOIN 後多出一列錯誤資料】

Closure

含圖解

Closure 通常指 attribute set 的閉包，例如 X⁺，代表從 X 出發，根據目前所有 FD 可以推導出的全部 attributes。白話來說，就是「知道 X 後，最多還能知道哪些欄位」。【建議畫圖：圖3 Closure 推導圖，A → B、B → C，所以 A⁺ = {A, B, C}】

Functional dependency

Functional dependency，FD，表示如果兩筆 tuple 的 X 值相同，Y 值也必須相同，就寫成 X → Y。白話來說，X 可以決定 Y。例如「學號 → 姓名」。

Normalization

Normalization 是把設計不好的 relations 拆成更小、更乾淨、更不容易出錯的 relations 的過程。白話來說，就是把一張又大又亂、資料重複很多的表拆成合理的小表。

Normal form

Normal form 是用來判斷 relation 是否符合某種正規化規則的標準。白話來說，就是資料表設計的健康等級，例如 1NF、2NF、3NF、BCNF。

Denormalization

Denormalization 是把已經正規化、較好的 relations 為了查詢效率或實作方便，重新合併成較大的 relations。白話來說，就是用資料重複與維護風險，換取查詢速度。

Superkey

Superkey 是一組 attributes，只要能唯一識別 relation 中每一筆 tuple，就稱為 superkey。白話來說，只要這組欄位能找到唯一一筆資料，就是 superkey。Superkey 可以包含多餘欄位。

Candidate key

Candidate key 是最小的 superkey，也就是不能再移除任何 attribute，否則就無法唯一識別 tuple。白話來說，就是剛剛好可以當資料身分證的欄位組合。

Primary key

Primary key 是從 candidate keys 中選出來，作為主要識別 tuple 的 key。白話來說，候選鍵可能很多個，但正式拿來當主鍵的是 primary key。

Secondary key

Secondary key 是 candidate keys 中，扣掉 primary key 後的其他 key。白話來說，它也能唯一識別資料，但沒有被選為正式主鍵。

Full functional dependency

Full functional dependency 表示在 X → Y 中，如果 X 是複合屬性，Y 必須依賴整個 X，不能只依賴 X 的一部分。白話來說，Y 要靠整組 X 才能決定，少一個欄位都不行。例如 {學號, 課程編號} → 成績。

Prime attribute

Prime attribute 是有出現在任何 candidate key 裡面的 attribute。白話來說，只要某欄位是候選鍵的一部分，它就是 prime attribute。

Non-prime attribute

Non-prime attribute 是沒有出現在任何 candidate key 裡面的 attribute。白話來說，就是不是拿來識別 tuple 的普通欄位。

Transitive functional dependency

含圖解

Transitive functional dependency 表示如果 X → Y，且 Y → Z，則 X 間接決定 Z，也就是 X → Z。白話來說，X 先決定 Y，Y 再決定 Z，所以 X 間接決定 Z。【建議畫圖：圖4 Transitive FD 圖，X → Y → Z】

Ch20：Transaction 與 ACID

Commit_transaction

Commit_transaction 是確認一個 transaction 正確執行完成，並讓它的修改正式生效。白話來說，就是交易成功，資料正式存進資料庫。

Rollback

Rollback 是當 transaction 沒有成功完成時，把整個 transaction 已經做過的修改全部取消。白話來說，就是交易失敗，全部倒回去，當作沒發生。

Undo

Undo 是使用 before image，把尚未成功 commit 或需要復原的 transaction 修改還原成舊值。白話來說，就是把資料改回交易之前的樣子。

Redo

Redo 是使用 after image，把已經 commit 但可能尚未真正寫入磁碟的修改重新做一次。白話來說，就是交易明明成功了，但系統當機可能還沒存好，所以要再寫一次。

System log

System log，也稱為 transaction log，是資料庫用來記錄 transaction 執行過程的紀錄，包含 begin、write、commit、abort、before image、after image 等資訊。白話來說，就是資料庫的操作紀錄本。

ACID

ACID 是 transaction 必須滿足的四個特性，包含 Atomicity、Consistency、Isolation、Durability。白話來說，ACID 是確保交易不會讓資料庫出問題的四大原則。

Atomicity

Atomicity，原子性，表示一個 transaction 裡的所有操作要嘛全部完成，要嘛全部不完成。白話來說，不能只做一半。例如轉帳不能只有扣錢沒有加錢。

Consistency

Consistency，一致性，表示 transaction 執行前後，資料庫都必須符合所有規則與限制。白話來說，交易不能把資料庫弄壞。

Isolation

Isolation，隔離性，表示多個 transactions 同時執行時，彼此不能互相干擾到造成錯誤結果。白話來說，大家可以同時操作，但結果不能亂掉。

Durability

Durability，持久性，表示 transaction commit 後，它的修改必須永久保存，即使系統故障也不能遺失。白話來說，只要資料庫說成功，就要真的存住。

Concurrency

Concurrency 是多個 transactions 在同一段時間內同時或交錯執行。白話來說，就是很多人同時操作資料庫。

Read_lock

Read_lock，也稱為 shared lock，是交易要讀取資料前取得的鎖。多個交易可以同時持有 read lock，但不能同時有 write lock。白話來說，大家可以一起看，但不能有人改。

Write_lock

Write_lock，也稱為 exclusive lock，是交易要修改資料前取得的鎖。同一資料項目同時間只能被一個 transaction 寫入。白話來說，我要改資料時，其他人先不能碰。

Ch21：Concurrency Control 與 Locking

Two-Phase locking(2PL)

含圖解

Two-Phase locking，兩階段鎖定，是一種 concurrency control 方法，transaction 分成 locking/growing phase 與 unlocking/shrinking phase。白話來說，前半段只能拿鎖，後半段只能放鎖，不能放鎖後又拿新鎖。【建議畫圖：圖5 2PL 時間軸，前段標 Growing Phase，後段標 Shrinking Phase】

Deadlock

含圖解

Deadlock 是一組 process 或 transactions 互相等待對方持有的資源，導致全部卡住。白話來說，你等我、我等你，誰都動不了。【建議畫圖：圖6 Deadlock 等待圖，T1 等 T2 的鎖，T2 等 T1 的鎖】

Starvation

Starvation 是某些 process 或 transactions 一直無法取得需要的資源，導致長時間沒有機會執行。白話來說，就是一直被插隊，永遠輪不到它。

Timestamp

Timestamp 是資料庫中用來標記 transaction 先後順序的時間戳或排序值。白話來說，就是每個交易的號碼牌，用來決定誰比較早、誰比較晚。

Locking(Growing) Phase

Locking 或 Growing Phase 是 2PL 的第一階段，transaction 可以取得新的 locks，但不能釋放任何 lock。白話來說，這階段只能一直拿鎖，不能放鎖。

Unlocking(Shrinking) Phase

Unlocking 或 Shrinking Phase 是 2PL 的第二階段，transaction 可以釋放 locks，但不能再取得新的 lock。白話來說，這階段只能放鎖，不能再拿鎖。

Conservative 2PL

Conservative 2PL 是交易開始前就先取得所有需要的 locks，如果拿不到就不開始。白話來說，先把全部資源借好再做事，因此可以避免 deadlock。

Basic 2PL

Basic 2PL 是交易執行過程中逐漸取得 locks，只要一開始釋放 lock，就不能再取得新 lock。白話來說，需要時才慢慢鎖，但仍遵守兩階段規則。

Strict 2PL

Strict 2PL 是交易執行過程中逐漸取得 locks，但 write locks 通常要等到 transaction commit 或 abort 後才釋放。白話來說，重要的寫入鎖會一路握到交易結束，避免其他交易讀到未提交資料。

Optimistic Concurrency Control

Optimistic Concurrency Control 是一種樂觀並行控制方法，假設大部分交易不會衝突，所以交易期間不先上鎖，等交易結束前再驗證是否違反 serializability。白話來說，先讓大家做，最後檢查有沒有撞車，有問題再 rollback。

Concurrency Control Enforcement

Concurrency Control Enforcement 是資料庫強制維持並行正確性的機制，如果交易違反 serializability 或造成衝突，可能會被 abort 或 rollback。白話來說，資料庫當裁判，發現交易會讓結果錯，就把它擋掉或退回。

Ch22：Recovery、Log、Buffer Policy

Before image(BFIM)

Before image，BFIM，是資料更新前的舊值。白話來說，就是 undo 時要用來改回去的值。

After image(AFIM)

After image，AFIM，是資料更新後的新值。白話來說，就是 redo 時要用來重新寫入的值。

Steal

Steal 表示 cache/buffer 中尚未 commit 的 transaction 修改，可以先被 flushed 到磁碟。白話來說，交易還沒確認成功，修改就可能先偷跑進硬碟。通常需要 Undo。

No-Steal

No-Steal 表示 cache/buffer 中尚未 commit 的 transaction 修改，不可以被 flushed 到磁碟，必須等 commit 後才可以寫回。白話來說，沒成功前不准真的寫進硬碟。通常不需要 Undo。

Force

Force 表示 transaction commit 時，相關修改必須立刻 flushed 到磁碟。白話來說，一提交就強制存檔。通常不需要 Redo。

No-Force

No-Force 表示 transaction commit 時，相關修改不一定馬上 flushed 到磁碟，可以延後寫入。白話來說，先說交易成功，之後再慢慢寫進硬碟。通常需要 Redo。

Write-Ahead Logging(WAL)

Write-Ahead Logging，WAL，表示資料真正寫回磁碟前，必須先把 log 寫入磁碟。白話來說，先寫操作紀錄，再改資料，這樣當機後才知道怎麼 undo 或 redo。

Shadowing Update

Shadowing Update 是修改資料時，不直接覆蓋原本資料，而是把新版本寫到其他磁碟位置。白話來說，舊資料先留著，新資料另外放，成功後再切換指標。

In-place Update

In-place Update 是直接用 cache 中的新版本覆蓋磁碟上的原資料。白話來說，就是在原本位置直接改掉資料。

Immediate Update

Immediate Update 是資料在 cache 中一修改，磁碟上的資料也可能立即或很快被修改，即使 transaction 還沒 commit。白話來說，還沒完全確定成功，就可能先寫進硬碟。通常需要 Undo，也可能需要 Redo。

Deferred Update

Deferred Update 是 cache 中的資料修改，等 transaction 結束或一定數量交易完成後，才寫入磁碟。白話來說，先記錄修改，確定成功後再真的寫入。通常不需要 Undo，但可能需要 Redo。

Ch18：Query Processing 與 Query Optimization

Query block

Query block 是查詢最佳化的基本單位，通常是一個 SELECT-FROM-WHERE 區塊，也可能包含 GROUP BY 與 HAVING。白話來說，就是一個可以被轉成 relational algebra 的最小查詢區塊。

Nested queries

Nested queries 是在一個 query 裡面又包含另一個 query block。白話來說，就是查詢裡面包查詢，內層查詢結果會被外層查詢使用。

Conjunctive selection

Conjunctive selection 是使用多個 AND 條件進行 selection。白話來說，就是同時符合多個條件才會被選出來。例如 salary > 30000 AND sex = 'F'。

Query graph

含圖解

Query graph 是用圖狀結構表示 query 或 relational algebra expression，通常節點代表 relation，邊代表 join 條件，旁邊標 selection 條件。白話來說，就是把 SQL 查詢畫成資料表關係圖。【建議畫圖：圖7 Query Graph，Employee、Department、Project 畫成節點，Join 條件畫成邊】

Query tree

含圖解

Query tree 是用樹狀結構表示 query 或 relational algebra expression，葉節點通常是 relation，中間節點是 select、project、join 等操作。白話來說，就是把 SQL 拆成一層一層的執行流程。【建議畫圖：圖8 Query Tree，底部放資料表，上面接 σ、⋈、π】

Heuristics Optimization

Heuristics Optimization 是用經驗規則改善查詢效率的最佳化方法。白話來說，不精算所有成本，而是用常識讓查詢變快，例如 selection 盡量先做、projection 盡量先做、先做能減少資料量的 join。

Ch17：Indexing

Dense index

Dense index 是 data file 中每一個 search key value，通常每筆資料或每個不同值，都有對應的 index entry。白話來說，幾乎每筆資料都有目錄項目。

Sparse index

Sparse index，也稱 nondense index，是只有部分 search key value 有 index entry。白話來說，不是每筆資料都建立目錄，只記一些代表位置。

Primary Index

含圖解

Primary Index 是建立在已排序 data file 的 ordering key field 上的 index，通常每個 block 有一個 index entry，指向該 block 的第一筆資料，也就是 block anchor。白話來說，資料本身已照主鍵排序，索引只記每個區塊的代表資料。【建議畫圖：圖9 Primary Index，一邊畫索引 key，另一邊箭頭指向排序資料檔 block】

Clustering Index

含圖解

Clustering Index 是建立在已排序 data file 的 non-key field 上的 index，每個 distinct field value 有一個 index entry，指向該值第一個出現的 data block。白話來說，資料照某個會重複的欄位分群，例如部門編號，索引指到每群的開頭。【建議畫圖：圖10 Clustering Index，不同部門編號指向各群資料開頭】

Secondary Index

含圖解

Secondary Index 是在已有主要存取方式的 data file 上，額外建立的輔助 index。它可以建立在 key 或 non-key field 上，通常 index 本身排序，但 data file 不一定依該欄位排序。白話來說，就是除了原本找資料的方法外，再開一條查詢捷徑。【建議畫圖：圖11 Secondary Index，左邊排序索引，右邊箭頭指向未排序資料檔】

補充：容易混淆的比較

Undo vs Redo

Undo 是把未完成或失敗交易改回 before image；Redo 是把已 commit 的交易重新套用 after image。白話來說，Undo 是倒回去，Redo 是再做一次。

Steal vs No-Steal

Steal 允許未 commit 修改先寫到磁碟，所以需要 Undo；No-Steal 不允許未 commit 修改先寫到磁碟，所以通常不需要 Undo。

Force vs No-Force

Force 要求 commit 時立刻寫到磁碟，所以通常不需要 Redo；No-Force 允許 commit 後晚點寫到磁碟，所以通常需要 Redo。

Primary Index vs Clustering Index vs Secondary Index

Primary Index 建在排序資料檔的 key 欄位上；Clustering Index 建在排序資料檔的 non-key 欄位上；Secondary Index 是額外輔助索引，資料檔不一定照該欄位排序。

2PL vs Strict 2PL

2PL 只要求先拿鎖再放鎖；Strict 2PL 進一步要求重要鎖通常要到 commit 或 abort 才釋放，因此更能避免讀到未提交資料。

Candidate Key vs Superkey

Superkey 可以唯一識別資料，但可能有多餘欄位；Candidate Key 是最小的 Superkey，不能再少欄位。

Prime Attribute vs Non-prime Attribute

Prime Attribute 有出現在某個 candidate key 裡；Non-prime Attribute 沒有出現在任何 candidate key 裡。
